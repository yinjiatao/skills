# Thinking Methodology v2.1

## 核心原则

先弄清用户知道什么、缺少什么，以及哪些盲区会改变结论，再调用思维工具。

本技能有三层：

```text
发现层：问卷 + 访谈，将未知变成已知
解释层：选择思维工具解释问题
行动层：把解释转化为可落地的执行方案
```

## 第一步：选择入口

### 直接处理

出现任一情况时，不启动问卷：

- 用户明确指定某个思维工具；
- 问题简单、边界明确；
- 用户已经提供足以交付的信息；
- 用户明确要求不要追问或立刻给方案；
- 用户只是要求改写、整理或解释已有内容。

直接处理时：

1. 使用用户已给信息完成请求；
2. 需要工具时读取 `references/tool-router.md`，再只读取被选中的工具文件；
3. 信息不足但不妨碍阶段性交付时，明确列出采用的假设和剩余未知；
4. 工具为可执行性补充用户未提供的数字、阈值或判断标准时，使用 `[建议值]` 或 `[待确认]` 标记，不得写成用户已经确认的要求；
5. 输出行动前读取 `references/delivery/executable-plan.md`，把分析转化为可以开始、推进、检查和调整的方案。

### 认知探索

出现任一情况时，进入问卷和访谈：

- 用户不知道自己真正的问题是什么；
- 用户进入陌生领域，不知道该问什么；
- 不同答案会导向明显不同的方案；
- 用户反复纠结，却无法解释原因；
- 存在明显隐藏假设、重大风险或高代价决定；
- 用户主动要求盲区扫描、反向采访或发现未知。

认知探索时，先完整读取：

- `references/discovery/questionnaire-interview.md`
- `references/discovery/unknown-discovery.md`

### 冲突优先级

1. 用户明确要求不要追问或立刻给方案，高于认知探索默认流程；输出阶段性方案并说明假设。
2. 用户明确指定工具，高于问题类别匹配；直接使用指定工具。
3. 已经提供的信息高于固定问题清单；不得重复询问。
4. 安全、法律、医疗或财务等高风险边界仍按上位规则处理，本技能不覆盖它们。

## 第二步：运行发现层

认知探索按以下状态顺序进行，不跳步：

```text
轻量问卷
→ 初始未知地图
→ 单问题访谈
→ 每五轮阶段总结
→ 用户选择继续、解释或行动
```

### 轻量问卷

- 一次展示 5—10 个问题；
- 使用 5 个基础问题，加最多 5 个按信息价值选择的动态问题；
- 删除用户已经回答过的问题；
- 问卷只确定探索方向，不试图一次收集全部资料。
- 用户明确要求盲区扫描时，问卷前先按 `questionnaire-interview.md` 输出不超过 5 个“待验证方向”；每项标记为 `[待验证假设]` 并明确说明不是用户事实。

### 初始未知地图

收到问卷回答后，先按 `references/discovery/unknown-discovery.md` 输出初始未知地图，再进入访谈。

所有内容必须区分：

- 用户确认的事实；
- 基于事实的暂时推断；
- 待验证假设；
- 尚未确认的未知。

“潜在的未知未知”只能写成可能的盲区、待验证假设或可能改变结论的变量，不能写成用户事实。

### 单问题访谈

- 每个助手回合只问一个访谈问题；
- 每题提供 3—5 个有区分度的选项；
- 始终允许自由回答和回答“不确定”；
- 优先询问答案会改变整体方案的问题；
- 不重复已经确认的信息；
- 根据用户回答更新内部未知地图和访谈计数。

### 每五轮阶段总结

完成第 5、10、15……个访谈问题后：

1. 立即停止继续提问；
2. 输出 `questionnaire-interview.md` 规定的阶段总结；
3. 让用户选择继续五轮、使用思维工具解释、直接整理行动方案、修改总结或自由回答；
4. 只有用户选择继续，才开始下一组访谈。

默认进行一至两组，即 5—10 轮访谈。信息已足够或用户要求结束时可以提前转入解释或行动。

## 第三步：运行解释层

只有在用户选择解释，或已经具备回答当前问题所需的信息时，读取 `references/tool-router.md`。

选择限制：

- 一个核心工具；
- 最多两个辅助工具；
- 如需行动转译，可再使用一个行动工具。

每个工具必须说明为什么适用，并引用问卷、访谈或用户背景中已经确认的信息。不得按问题类别默认串联固定工具链。

## 第四步：运行行动层

输出行动方案前读取 `references/delivery/executable-plan.md`。

- 方案范围匹配用户明确请求：用户要下一步就聚焦下一步，用户要完整周期就覆盖完整周期；
- 把任务拆成有顺序的具体动作，并为关键步骤写清阶段产出和完成标准；
- 第一项动作必须足够具体，但不得因此隐藏完成任务所需的后续步骤；
- 必要时提供可以直接使用的模板、话术、字段或示例；
- 说明关键依赖、卡住时的替代动作以及需要调整方案的条件；
- 不根据未确认的推断删减用户明确要求的方案范围。

## 最终输出

根据问题动态增减，默认按以下顺序组织：

1. **未知地图**：已经确认什么，还有什么没有确认；
2. **核心发现**：用户最初认为的问题与当前真正问题之间的变化；
3. **思维工具解释**：工具为何适用，它解释了什么；
4. **行动方案**：下一步、完成标准和调整条件；
5. **剩余未知**：哪些假设仍可能改变结论。

直接处理简单请求时，只保留完成请求所需的部分，不强行输出完整模板。

## 停止与切换条件

- 用户说“别问了”“直接给方案”或同义表达：立即停止问卷/访谈，输出阶段性方案和假设。
- 用户指定工具：切换到直接处理。
- 用户选择阶段总结中的 B 或 C：分别进入解释层或行动层。
- 用户修改总结：先修正未知地图，再决定是否继续。
- 新信息推翻关键假设：回到未知地图，明确指出结论为何需要调整。

## 质量检查

每次输出前确认：

- 是否问了用户已经回答过的问题？
- 当前问题的答案是否真的可能改变方案？
- 是否把推断或风险误写成用户事实？
- 是否超过一个核心工具和两个辅助工具？
- 工具分析是否引用了已确认信息？
- 行动方案是否覆盖用户要求的范围，并包含具体动作、阶段产出和完成标准？
- 第五轮之后是否先总结并停止提问？

## 常见错误

- 对所有复杂问题强行问卷；
- 问卷之后直接给方案，跳过未知地图；
- 一次提出多个访谈问题；
- 把“未知的未知”写成吓人的确定性风险；
- 用多个工具制造分析很完整的错觉；
- 用户要求立刻行动时仍坚持收集全部信息；
- 用户要求完整计划时只展示第一步；
- 使用“整理、完善、推进”等抽象动作，却没有说明产出和完成标准。
